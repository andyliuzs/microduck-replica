# 语音 AI 对话接入(豆包实时语音)

日期:2026-11-11。来源:用户确认三项决定——接豆包实时语音;双回答模式(默认按回复文字配鸭叫,说"说人话"或网页切换才用人声+网页文字);首版就带 AI 指挥动作(白名单)。功能归 F26。

状态:**代码与离线自测完成,尚未在鸭子真机、真实云端 Key 下验收**。本文是接入说明与当前边界,不是真机验收记录;真机验收见[验证记录](superpowers/verification/2026-11-11-realtime-voice.md)的后续补充。

## 使用方式

1. **开通账号(用户自己做)**:火山引擎控制台 → 语音技术 → 端到端实时语音,创建应用拿 **API Key**(新版控制台 `X-Api-Key`;与方舟文字模型的 Key 不是同一个)。
2. **网页配置**:设置 → AI 对话 → 新建连接,提供商选「豆包·实时语音」,填连接名、API Key(音色 ID 可留空,默认 `zh_female_vv_jupiter_bigtts`),保存并「设为当前」。实时语音连接不支持文字测试/试聊。
3. **开始对话**:遥控页「语音与音乐互动」→ AI 对话 →「开始对话」(会自动带起监听),或直接按 R3 后在面板开启。按 R3 关闭监听即结束对话;对话空闲约 5 分钟自动挂断(省话费)。
4. **回答方式**:默认鸭叫——AI 回复只显示在网页字幕,并按回复文字配一声(疑问配 inquire、开心配 chirp、道歉配 coo 等)。说"说人话"或点面板按钮切换为人声(TTS 从鸭子扬声器播出)+ 网页文字。
5. **AI 指挥动作**:云端工具调用白名单——坐下、站起来、点头、摇头、歪头、张嘴、六种叫声;坐/站带姿态回读确认,更新中自动拒绝,头部动作需已开始走(策略在跑)。

## 架构

```
麦克风(duck-echo 独占)
  └─ dialogue_bridge.py ──audio.sock(JSON行协议,16k mono PCM/mute/unmute)──┐
                                                                            │
Studio realtime_voice.py(WS 客户端 + 会话状态机 + 工具执行)◄────────────────┘
  ├─ wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue(X-Api-Key)
  │    session.create(model 1.2.6.1, pcm 16k 进 / pcm_s16le 24k 出, tools)
  ├─ 字幕/状态 → 网页 WS 广播 {"t":"dialogue",...}
  ├─ 人声模式:TTS PCM → 桥(aplay 流式播放,期间麦克风自抑制=半双工)
  ├─ 鸭叫模式:回复文字分类 → 桥 robot.sound(走 cue 通道,自带抑制)
  └─ 工具调用 → DialogueActions(rpc.Conn 直连 robotd,坐/站回读同 duck-echo 语义)
```

- **duck-echo 保持无网络沙箱**(AF_UNIX only 不变);云连接、Key、字幕都在 Studio。桥是单客户端 unix socket(`/run/duck-echo/audio.sock`,0600),复用 control.sock 的一行 JSON 风格。
- **自抑制对应云端静音**:鸭子出声(提示音/TTS/叫声)期间桥不发 PCM 并发 `mute`,Studio 转发 `input_audio_mute.commit`(官方协议要求静音必须显式上报,否则会话超时);恢复后 `unmute`。半双工,不支持打断(二期)。
- **互斥**:对话与音乐模式互斥;对话期间本地坐站口令不执行(交给云端工具);关监听(R3)一并关对话。
- **计费护栏**:会话由 R3/面板显式开关;空闲 300 秒自动 `session.close`;云端起不来时自动关掉 duck-echo 的对话开关(麦克风不空跑)。

## 协议核对结论(2026-11-11,含真实云端实连)

- 端点 `wss://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`,鉴权头 `X-Api-Key`(新版控制台);`session.model` 固定 `1.2.6.1`。
- JSON 文本帧事件:`session.create/update/close`、`input_audio_buffer.append`(base64,约 20ms/640B)、`input_audio_mute/unmute.commit`、`conversation.item.create`(上下文+工具结果 role=tool 带 call_id)、`response.cancel`;下行 `session.created`、`conversation.item.input_audio_transcription.*`(用户话)、`response.output_text.delta`、`response.output_audio.delta`(base64 PCM)、`response.function_call_arguments.done`、`response.done`、`error`。
- 音频 **PCM 直进直出**:输入 pcm/16000,输出可配 `pcm_s16le/24000`——不需要 opus 编解码。输出频率由 aplay 经 plughw 转换到硬件。
- **实连修正(与文档摘要不同的真实字段)**:识别完成事件的文字在 **`text`** 字段(非 transcript);工具调用在 **`items` 数组**里(一次可多个),每项 `{call_id, name, arguments}`;**unmute 后音频流不能停**(静音也要持续推),否则约 30-40 秒后云端报 `AudioTTSIdleTimeoutError`——鸭子的桥持续推流,天然满足。
- **真实闭环已验证(电脑端,用户 API Key)**:合成语音→识别"你好，小鸭子，请坐下。"→工具调用 duck_action(sit)→结果回填被接受→AI 语音回答"乖乖坐好啦，有什么事都可以跟我说哦。"(3.4s TTS,usage 6121 tokens);错误 Key 在握手阶段被 401 拒绝。未在鸭子上跑。
- 官方依据:[端到端实时语音接入必读](https://docs.volcengine.com/docs/doubao-voice/access-must-read)、[全双工版](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version)。

## 已知边界(本期不做/待验证)

- **未在真机验收**:真实 Key 的时延、WiFi 下表现、音乐干扰、长时间会话稳定性都待 duck-0de6 实测后补记录。
- 打断(barge-in)、免唤醒词("小鸭小鸭"离线唤醒)、连续免按键对话留二期;现在必须 R3/面板开关会话。
- 鸭叫分类器是关键词规则,真机验收后按实际回复语料调;说人话切换靠 LLM 工具调用,不保证 100% 命中(网页按钮是确定路径)。
- 更换回答方式对已开始的这轮回答立即生效(音频播不播由 Studio 决定),但 `instructions` 里的模式提示要到下一条回复才反映;影响很小。
- 计费、并发、QPM 限制以火山控制台为准;Studio 不做用量统计。
