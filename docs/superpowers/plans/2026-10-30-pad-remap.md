# Controller remapping implementation plan

**Goal:** Persist user-learned controller mappings and use the same mapping for display and real padd control.

**Architecture:** A new bounded local padd mapping control socket owns raw snapshots, persisted profiles and an authoritative output gate. Studio owns per-page learning UX and calls that socket; the web page never writes a profile without native acknowledgement.

**Tech Stack:** Rust/serde/evdev/padd, Python 3.13, Preact/htm, Node and headless Edge. Dedicated native and Studio worktrees.

## Tasks

- [ ] Native implementation: `padd/src/remap.rs` (or focused submodules), tap raw snapshot lifecycle, main-loop source/gate integration, persisted StateDirectory and CLI paths. TDD before implementation, exact protocol from design doc. Test native control gate and all input roles.
- [ ] Native spec review, then code quality review; resolve findings before considering native task complete.
- [ ] Studio implementation: `studio/pad_mapping.py` with bounded client, learning state and conn ownership; `pad.py` integration, updater/other motion guards; no blocking socket I/O from snapshot/event loop. Tests cover code recognition, axis sweep/neutral, conflicts and capability errors.
- [ ] Web implementation: `web/pad-mapping.js`/`.css`, entry and current diagram integration in `pad.js`, local stylesheet load. Every key selectable, instructions for directions/triggers, live test, incomplete/invalid state, save/cancel/default and lifecycle cancellation.
- [ ] Run real browser integration with loopback native-contract fixture, inspect desktop/phone screenshots, prove no motion requests during learning. Run related existing pad/auth/API tests.
- [ ] Cross-build ARM64 padd and check identity/help; document which component must update, StateDirectory integration and real-device acceptance limits. No public release or live deployment in this task.
- [ ] Final independent spec/quality review, update implementation/verification docs, commit local feature and preserve worktrees plus previous SSH guide.
