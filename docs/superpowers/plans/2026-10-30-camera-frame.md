# Camera preview frame layout

**Goal:** Remove the wide dark surround around portrait camera previews while preserving the complete, correctly rotated image below the posture card.

**Design:** Keep the existing camera card and session lifecycle. During playback only, size the inner video frame to the actual rotated image aspect ratio, center it, and bound it by both available width and a viewport-dependent height. The normal playback height budget is 240–420 px (desktop minimum 280 px). “放大 / 还原” changes this same card in place: expanded height is bounded by `clamp(360px, 72vh, 840px)` and available width. It must not navigate, replace the video element/MediaStream or reconnect WebRTC. Allow the established overflow guard to make the left stack scroll when a larger preview cannot fit. Unavailable/loading placeholders retain their readable full-width area and previous compact height. Do not crop, stretch, change installation rotation, restart robotd, or change exposure to hide a dark camera image.

**Architecture:** `CameraScreen` supplies the displayed aspect ratio as a CSS custom property. `sensors.css` uses that ratio and a bounded height for a centered playback frame. `InlineCamera` owns a local expanded boolean; its button exposes `aria-pressed`, and a data attribute changes only the CSS playback-height budget. The camera session effect does not depend on this flag. The dedicated camera page remains independently accessible from navigation; the inline zoom button never opens it.

**Tech stack:** Preact, CSS, Python unittest, real headless Edge with a canvas video fixture.
